# 21. Serving LLMs Efficiently

## The Inference Problem

Inference is continuous. Making it efficient is critical for cost, latency, and throughput.

## KV Cache

Reuse Key and Value vectors to avoid recomputing:

```
Without: 100 tokens = 5,050 computations
With: 100 tokens = 100 computations

50x speedup!
```

Memory cost: ~9 MB per token per sequence for GPT-3.

## Continuous Batching

Traditional batching waits for all requests to finish. **Continuous batching** adds new requests when old ones complete:

```
Request finishes → add new request
Keeps GPU utilized
Requests don't wait
```

## Quantization

Use lower precision (fewer bytes per number):

```
float32 → int8: 4x smaller
Minimal quality loss
```

### Methods

- **PTQ** (Post-Training): Convert after training (easy, lower quality)
- **QAT** (Quantization-Aware): Train knowing quantization (better quality)

## Speculative Decoding

Draft multiple tokens quickly with small model, verify with main model:

```
Small: Predict tokens 1-3
Main: Verify match
Accept: Keep all 3
2-3x faster!
```

## Inference Optimization Checklist

```
☐ Use KV cache
☐ Enable continuous batching
☐ Quantize (int8 or float16)
☐ Consider speculative decoding
☐ Use optimized server (vLLM)
☐ Batch requests
☐ Cache embeddings for RAG
☐ Use smaller models when possible
```

## vLLM and Frameworks

**vLLM**: Popular inference server with continuous batching, KV cache management, efficient kernels.

Result: 5-10x throughput vs naive inference.

Other frameworks: Text Generation WebUI, LLaMA.cpp, Ollama, HuggingFace TGI

## Hardware

For inference, use GPUs:
- H100: ~50,000 tokens/sec
- A100: ~20,000 tokens/sec
- L40: ~10,000 tokens/sec

Multiple smaller GPUs > one huge GPU (better utilization).
